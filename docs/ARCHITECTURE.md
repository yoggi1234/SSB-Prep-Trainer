# Architecture

SSB Prep Trainer is a Windows Electron app with **no runtime npm dependencies**. It has two
compartments that share a window but no data:

1. **The SSB trainer** — TAT, WAT, SRT, word library, lecturette, history. Pure JavaScript and
   bundled JSON/image assets.
2. **The News Digest** — a separate Python CLI (`digest-tool/`) driven as a child process. It was
   copied unchanged from its own project; it keeps its own config, drafts, inbox and output.

Nothing on the SSB side calls an AI, and nothing leaves the machine unless the user turns on the
optional online switches.

## Process model

| Process | File | Responsibility |
| --- | --- | --- |
| **Main** | `src/main.js` (~2,300 lines) | Window, JSON store, data packs, native dialogs, file export, HTTP for the optional online features, Python engine lifecycle, log file, smoke suite |
| **Preload** | `src/preload.js` | The only bridge. `contextBridge.exposeInMainWorld('api', …)` exposing one named function per IPC channel |
| **Renderer** | `src/renderer/` | Interface only. `app.js` (~3,800 lines, vanilla ES5-style JS), `styles.css`, `index.html` |

`webPreferences`: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: false`,
`backgroundThrottling: false` (timers must keep running when the window loses focus),
`spellcheck: false`. The renderer therefore cannot touch Node or the disk directly; every action is
an `ipcRenderer.invoke` through `window.api`.

`index.html` carries a strict Content-Security-Policy with `connect-src 'none'`, so the page cannot
make a network request even if asked. Online lookups happen in the main process.

## Renderer shape

There is **no framework and no build step**. Screens are functions that return an HTML string and
write it into the shell:

- `goto(view)` sets `S.view` and calls the matching `render…()` function (`home`, `library`,
  `history`, `settings`, `lecturette`, `digest`, `diagnostics`, and the run screens `tat`, `wat`,
  `srt` plus their result views).
- `body(html)` replaces the screen container; event listeners are attached immediately afterwards
  with `document.getElementById(...).addEventListener(...)`.
- State lives in `S` (a plain object) plus per-test run objects (`RUN`, `WAT`, `SRT`, `DG`).
- Timers are `setInterval` ticks with a monotonic deadline, not accumulated decrements, so a slow
  frame cannot make the clock drift.
- `esc()` is used for every value interpolated into HTML.

Adding a screen means: add an entry to `TILES` (the dashboard is the only navigation — there is no
sidebar or top menu), add a branch in the router, write `renderX()`, and add a check to the smoke
suite. Tiles carry `test: true` only for the three tests, which open the setup screen instead of a
view. `wireDash()` owns the highlight: a 4.5 s rotation that stops on hover, focus or a key, and
arrow-key movement sized by the computed grid column count.

## Main process areas

| Area | What to know |
| --- | --- |
| Store | `app.getPath('userData')/ssb-prep-store.json`. `defaults()` defines the schema; `getStore()` merges on read; `persist()` writes pretty JSON. Attempts are capped at 300. Also holds `tatBin` (pictures taken out of the test) and `tatGone` (their ids after a permanent delete, so a bundled picture cannot come back). |
| Data packs | Read-only JSON under `data/` (`wat.json`, `srt.json`, `tat.json`, `lecturettes.json`, `tat-images.json`, `tat-classic.json`, `wat-hints/`). Loaded once on first use, cached. `lecturettes.json` (334 topics) is generated by `tools/build-lecturettes.py` from `lectures.json` (hand-written), `lecturettes.part*.json` (drafted scripts), `lecturette-topics.json` (the 137-topic master list) and `lecturette-topics-extra.json` (198 topics imported from the user's PDF by `tools/import-lecturette-pdf.py`); the inputs are build sources and are excluded from the package. |
| TAT bin | `tat:remove` copies a bundled picture into `userData/tat-bin/` and records it; `binnedKeys()` hides binned and permanently deleted ids from `tat:library`, `tat:classic` and `tat:images`. `tat:restore`, `tat:purge`, `tat:emptyBin` and `tat:resetGone` manage it. User files are never deleted from disk. |
| Lecturette points | `lectures:live` fetches up to eight Google News points for a topic, writes `userData/live-data/<id>.json` plus an `index.json`, and reuses the copy for 90 days. A failed or refused fetch returns the saved copy flagged `offline: true`; it never deletes it. |
| Dictionary | 149,003 words shipped as data, indexed lazily in the main process on first library use. |
| Network | Only for optional features: Datamuse (word/meaning/topic), Art Institute of Chicago + The Met (pictures), Google News (lecturette topics). `onlineAllowed()` gates every call. |
| Digest | Resolves Python, checks the four libraries, copies the engine into user data on launch, spawns `python -m newsdigest …`, streams stdout/stderr to the renderer. |
| Logging | `initLogger()` wraps `console.log`/`console.error`, captures `uncaughtException` and `unhandledRejection`, and appends to a rotating file. |
| Smoke | `runSmoke()` is the executable specification (see `docs/DEBUGGING.md`). |

## IPC surface

Everything the renderer can do, by channel prefix:

- `data:load`, `config:get`, `config:set`
- `attempts:list`, `attempt:add`, `attempt:delete`, `attempts:clear`, `export:text`
- `tat:images`, `tat:pick`, `tat:clearImages`, `tat:library`, `tat:classic`, `tat:online`
- `dict:get`, `dict:info`, `dict:random`, `dict:search`, `dict:sentiment`
- `lectures:list`, `lectures:hot`, `lectures:live`, `lectures:liveStatus`
- `news:index`
- `tat:bin`, `tat:remove`, `tat:restore`, `tat:purge`, `tat:emptyBin`, `tat:goneCount`, `tat:resetGone`
- `online:status`, `online:words`, `online:meaning`
- `wat:hints`
- `digest:status`, `digest:run`, `digest:cancel`, `digest:config:get`, `digest:config:set`,
  `digest:files`, `digest:open`, `digest:pickPdfs`
- `power:block`, `shell:open`
- `log:append`, `log:tail`, `log:openFolder`
- `diag:info`, `diag:save`

Two event channels push from main to renderer: `digest:log` and `digest:done` (wired in
`wireDigestEvents()` through preload's `onDigestLog` / `onDigestDone`).

## Storage layout

```
%APPDATA%\SSB Prep Trainer\
  ssb-prep-store.json        settings, custom sets, own picture paths, the TAT bin, last 300 attempts
  live-data\                 saved lecturette points (one JSON per topic), index.json, _news-index.json
  tat-bin\                   copies of bundled pictures moved to the bin, for restore
  logs\app.log               runtime log (rotates to app.old.log at 2 MB)
  news-digest\               the digest engine's own world
    newsdigest\              code, refreshed from the package on every launch
    config.json              created once, never overwritten afterwards
    output\  drafts\  inbox\  state\  user_data\
```

The SSB store and the digest folder are deliberately disjoint. Nothing in the digest tab reads
`ssb-prep-store.json`, and nothing in the SSB tabs reads the digest folder.

## Packaging

`electron-builder --win --x64` produces an NSIS installer and a portable `.exe`.

- `files`: `src/**/*`, `data/**/*`, `NOTICE.txt`, `package.json` → inside `app.asar`.
  `!data/lecturettes.part*.json` and `!data/lecturette-topics.json` keep the build sources out of the
  package; only the merged catalogue ships.
- `extraResources`: `digest-tool/` → `resources/digest-tool`, **outside** the asar, because Python
  cannot import from an asar archive. `__pycache__`, `output`, `drafts`, `state`, `user_data` and
  `inbox` are filtered out.
- `tools/verify-package.js` reads `app.asar` directly and compares each packaged file with the
  working tree, then counts the picture libraries. A rebuild is only trustworthy if it passes.

## Theme

Two palettes, one token list. Every colour in `styles.css` is drawn from custom properties declared
once in `:root`; the second palette redefines the same list under `:root[data-theme='mist']` and
nothing else. Nothing outside that block may hard-code a colour — a literal `#fff` in a rule is a
bug, because it cannot follow a palette switch.

| Token | Mist (dark, shipped) | Alpine light |
| --- | --- | --- |
| `--bg` ground | `#0e1a15` | `#e8f1ec` |
| `--panel` / `--panel-2` | `#16261f` / `#1b2d25` | `#f8fcfa` / `#eef6f1` |
| `--text` body ink | `#e6efe9` | `#12251b` |
| `--accent` / `--on-accent` | `#64bf71` / `#07130c` | `#2f7150` / `#ffffff` |
| `--danger` | `#e07a63` | `#a13c2c` |

Surface tokens (`--field`, `--wash`, `--tint`, `--card-1/2`, `--track`, `--log-bg`, shadows, …)
carry the panels, inputs, sheets and the digest log, so both palettes keep the same layout and the
same motion. Two values are deliberately never themed: `--frame` (white) and `--mat` — a photograph
always sits on a white mat.

The active palette is `config.theme` in the store (`mist` by default, `alpine` optional), applied
in the renderer by `applyTheme()` before first paint and mirrored in the BrowserWindow's
`backgroundColor` so the first frame is already the right ground. The Mist palette comes from the
Windows 11 "Mist" theme by WinX Customization (its preview, wallpaper and Windhawk styler files);
Alpine light keeps the sage-paper identity the app shipped with first.

Rules: green is emphasis, progress and state — not body copy. Terracotta/red is reserved for
destructive actions and urgent clocks. TAT pictures are shown up to 56vh with a soft shadow on a
white mat, never behind a tint or overlay. Verify colours from computed styles in the running app,
not by reading the CSS file; the smoke asserts the ground, the ink and a 7:1 body-text contrast for
both palettes, and that `prefers-reduced-motion` stops every animation.

## Intentional constraints

- **Offline by default.** The online switches in `defaults()` control the optional features only;
  the CSP (`connect-src 'none'`) blocks the page itself from the network regardless, so every
  request is made by the main process or not at all.
- **No bundler.** The renderer is loaded as plain files; editing `app.js` and restarting is enough.
- **No dependencies.** Anything new must justify itself against a zero-dependency baseline.
- **Python is not bundled.** The digest tab detects and explains a missing runtime instead of
  silently failing.
